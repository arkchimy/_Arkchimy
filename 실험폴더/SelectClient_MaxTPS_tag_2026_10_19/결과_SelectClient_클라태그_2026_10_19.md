# Select 클라 루프 지연 원인 — 클라 호출별 태그 (루프백, 2026-10-19)

## 측정 목적
이전 측정(`SelectClient_MaxTPS_2026_10_19`)에서 AcceptEx w2·w4일 때 클라 루프 1회가 ~50ms였다. 어느 호출에서 시간이 드는지 본다.

## 측정 조건
- 이전과 동일: 클라 `FloodClient_Select_t8_o0`(8스레드×64, select timeout 0), 서버 accept w1 / AcceptEx w1·w2·w4(slotCnt 1000), 3회, 회차마다 서버 순서 변경.
- 클라에 임시 태그 추가: `socket()`, `connect()`, `select()`, `closesocket()`.

## 관찰
- **클라 연결 1건에 ~700~800us가 든다** (socket ~80~180 + 논블로킹 connect ~370~540 + closesocket ~230).
  스레드 8개면 클라 상한 ≈ 8 ÷ 780us ≈ **10.3k/s** → 실측 클라 연결TPS 10.4~10.6k와 맞는다. **w2·w4에서는 클라가 상한에 걸려 있다.**
- **루프 50ms의 정체**: 특정 호출 하나가 막히는 것이 아니다. 서버가 빨리 받아주면 루프마다 64개가 전부 완료되어, 64 × ~780us ≈ 50ms가 된다.
- **논블로킹 connect가 370us 이상 걸린다.** 바로 반환해야 할 호출이 비싸다. 루프백에서는 SYN을 보내는 호출 안에서 수신 측(서버 쪽) TCP 처리까지 같이 수행되는 것으로 보인다(추정). closesocket(RST 송신)도 같은 이유로 ~230us.
- 클라CPU 31%(≈ 4.4코어) / 스레드 8개 → 클라 스레드도 시간의 절반가량은 CPU 밖에서 대기.

## 주의
- 태그 추가로 TPS가 이전 측정보다 약간 낮다(accept w1 7.6k→6.8k, AcceptEx w4 10.1k→7.9k). 회차 간 편차도 크다.
