# RSA 에코 대 AES 에코 PC B 측정 (2026-11-19)

PC B(i5-8600, 6코어 6스레드, 하이브리드 아님), 커밋 `edfb06d`. 서버 워커 2, 클라 묶음 4, 수명 10–30초.
두 서버는 접속·가입·로그인이 같고(RSA) 에코만 다르다 - RSA는 요청마다 OAEP 풀기 + 서명, AES는 로그인 때 받은 세션 키로 AES-256-GCM.
프로파일러 값은 두 워커를 횟수로 가중해 합쳤다(`tools/echo_compare/merge.ps1`).

## 30분 시험 (세션 64·스레드 4)

AES 09:03–09:33, RSA 09:33–10:03. 둘 다 프로토콜오류·예상밖끊김 0, 수락 = 해제, 잘못된패킷 0.

| 항목                 | RSA       | AES         | 배      |
| -------------------- | --------- | ----------- | ------- |
| 에코/s (클라 중앙값) | 1,574     | 139,976     | 약 89   |
| 서버 에코 수         | 2,823,140 | 260,082,092 |         |
| 서버 에코 하나       | 1.17ms    | 1.16us      | 약 1000 |
| 풀기                 | 0.58ms    | 0.32us      |         |
| 잠그기(+서명)        | 0.59ms    | 0.26us      |         |
| 서버 CPU(코어)       | 1.88/2    | 0.17/2      |         |
| 서버 CPU/에코        | 1.19ms    | 1.21us      | 약 990  |
| 클라 CPU(코어)       | 2.03      | 0.23        |         |
| 접속(키 쌍 만들기)   | 5,790     | 5,814       |         |
|                      | (1,188)   | (1,190)     |         |

- RSA는 서버가 포화(워커 2 = 2코어 중 1.88), AES는 서버도 클라도 놀았다
- 서버 CPU/에코 = 서버 CPU 평균 ÷ 에코/s(계산 값). 프로파일러의 에코 하나 시간과 같은 크기라 두 측정이 서로 맞는다
- AES의 풀기·잠그기는 최소가 0.20us(측정 바닥)라 항목별 비율은 참고만 - 비교는 에코 하나와 CPU/에코로
- AES `Echo total`(1.16us)이 구간 합(0.71us)보다 큰 것은 태그 다섯 개의 측정 비용이 섞여서다
- RSA 30분 값은 어제 37분 시험(요청 1.18ms, 초당 1,560)과 같다
- 접속 처리(ServerHello 서명·키 쌍)는 두 서버가 같다 - Handshake total RSA 12.6ms, AES 11.5ms

## 30초 시험 (세션·스레드 4조건)

| 세션·스레드 | AES/s   | AES 에코 | 풀기   | 잠그기 | RSA/s | RSA 요청 |
| ----------- | ------- | -------- | ------ | ------ | ----- | -------- |
| 1·1         | 2,160   | 5.09us   | 1.87us | 1.05us | 404   | 1.06ms   |
| 4·1         | 9,824   | 3.13us   | 1.13us | 0.69us | 944   | 1.05ms   |
| 16·2        | 36,752  | 1.62us   | 0.51us | 0.38us | 1,573 | 1.07ms   |
| 64·4        | 137,502 | 1.13us   | 0.31us | 0.26us | 1,612 | 1.12ms   |

- 에코/s는 클라 중앙값, AES 에코·풀기·잠그기와 RSA 요청은 서버 평균
- RSA 값은 어제 PC B 30초(`실험폴더/rsa_echo_pcb_2026_11_18/`)
- AES 에코/s는 세션 수에 비례한다(1 → 64세션에 64배). 세션마다 4개를 보내고 다 받아야 다음이라, 에코/s ≈ 세션 × 4 ÷ 한 바퀴 시간이고 한 바퀴가 약 1.8ms(계산 값 - 클라 select 루프와 루프백 왕복으로 보지만 나누어 재지는 않았다)
- AES 에코 하나는 한가할수록 길다(1·1 5.09us → 64·4 1.13us). 코어가 쉬다 깨어나는 비용으로 보지만 확인하지 않았다
- RSA는 16세션부터 워커 2 포화로 에코/s가 약 1,600에서 멈춘다

## 파일

- `30s/s<세션>_t<스레드>/`, `30min_aes/s64_t4/`, `30min_rsa/s64_t4/`: `server.txt`·`client.txt`(CP949), `profiler.txt`
- `cpu_samples.csv`: 시험 중 2초마다 서버·클라 프로세스가 쓴 코어 수
- 다시 돌리기: `.\tools\echo_compare\echo30.ps1 -Kind Aes|Rsa -Cases '64:4' -RunSec 1800 -OutRoot <상대 경로>` → `merge.ps1 -Root <같은 경로>`. `-OutRoot`는 현재 폴더 기준 상대 경로만 된다
