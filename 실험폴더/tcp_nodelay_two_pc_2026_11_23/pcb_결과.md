# TCP_NODELAY 두 PC 측정 - PC B(게임 서버) 쪽 기록 (2026-11-23)

채팅 왕복 시간(봇 `[lat]`)은 PC A 세션이 정리한다. 여기는 PC B 게임 서버의 시작 설정·CPU·메모리·오류다.

## 조건

- 게임 서버만 PC B(i5-8600, 192.168.45.149, 유선 1Gbps)
  - MySQL·Redis·로그인 서버·채팅 봇 30은 PC A(192.168.45.97)
- `tools/game/offload_pcb.ps1 -Mode A -NoDelay 0|1`
  - server.cfg의 tcpNoDelay를 잠시 바꿔 띄우고 바로 되돌림
  - 1초마다 게임 서버 CPU 시간 차이(코어)·사설 메모리
- 시작 줄로 적용 여부 확인
  - 끔: `[main] 네트워크: 워커 2, TCP_NODELAY 끔(Nagle)`
  - 켬: `[main] 네트워크: 워커 2, TCP_NODELAY 켬`

## 구간

| 폴더            | tcpNoDelay | 기록              | 봇 접속 중(초) |
| --------------- | ---------- | ----------------- | -------------- |
| `pcb_nd0_part1` | 0          | 06:50:01–06:56:28 | 235            |
| `pcb_nd0`       | 0          | 06:57:10–07:31:58 | 1,279          |
| `pcb_nd1`       | 1          | 07:32:16–08:02:43 | 792            |

- 봇 접속 중 = 게임 서버 통계의 세션이 25 이상인 초
- `pcb_nd0_part1`은 12분으로 띄운 첫 서버
  - 사용자 요청으로 180분 기록으로 바꾸려고 06:56에 정상 종료하고 다시 띄웠다
  - 그 사이 회차는 없었다(세션 0)
- `pcb_nd0`의 두 번째 서버는 07:32 TCP_NODELAY 켬으로 바꿀 때 세션 30이 남은 채 껐다
  - 마지막 통계가 수락 1,056 / 해제 1,026인 이유
  - 그때 돌던 PC A 회차는 중간에 끊겼을 수 있다
- 기록 스크립트가 다시 띄울 때 시작 확인을 잘못해 먼저 끝났다
  - 이전 서버의 출력과 종료 순간을 읽었다
  - 06:57부터는 이미 떠 있는 서버에 붙어 1초마다 기록하는 작업으로 이어 적었다
  - 같은 형식의 `game_proc.csv`다
