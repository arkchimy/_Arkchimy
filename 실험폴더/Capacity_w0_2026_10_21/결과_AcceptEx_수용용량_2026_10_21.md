# AcceptEx 수용 용량 확인 — 걸어둔 소켓이 백로그 칸을 같이 쓰는가 (루프백, 어댑터, 2026-10-21)

## 목적
걸어둔 AcceptEx 소켓이 백로그(200칸)와 별도 공간인지(용량 = 200 + slotCnt), 백로그 칸을 같이 쓰는지(용량 = 200) 확인한다.
같은 용량 비교 실험에서 AcceptEx 쪽 용량을 맞추기 위한 사전 확인이다.

## 조건
- 서버: 기존 바이너리(10/20 측정과 같은 파일), AcceptEx, **워커 0개**, backlog 200, slotCnt 300 / 100.
  워커가 없으므로 완료 통지를 꺼내지 않고 재등록도 하지 않는다. 걸어둔 소켓은 한 번씩만 쓰이고, 그 뒤 연결은 백로그에 쌓이기만 한다.
- 클라: `FloodClient_Select_t8_o100`(동시 512개), 코드 수정 없음. 성공 후 RST로 끊지만 백로그에서 빠지지 않는다(이전 확인 사항).
- 성공 total이 멈춘 값 = 수용 용량. 각 10~30초.
- 시작 전 포트 32000 잔여 연결 0, 어댑터 연결(BatteryStatus 2).

## 결과
```
slotCnt   성공 total (1회차 / 2회차)   예측: 별도(200+N) / 공유(200)
-------   -------------------------   ---------------------------
300       500 / 501                   500 / 200
100       303 / 306                   300 / 200
```
- 첫 1초에 total이 위 값까지 오르고 그 뒤로는 멈춘다. 이후 약 2초마다 FailTPS=512(동시 진행 512개가 전부 거절).
- 서버 측 `Get-NetTCPConnection`에는 Listen 1개만 남았다(클라가 RST로 끊은 연결은 TCP 연결 목록에서 사라짐). 그래도 백로그는 찬 상태로 유지됐다.

## 해석
- **걸어둔 AcceptEx 소켓은 백로그 칸과 별도 공간이다. 수용 용량 = backlog + slotCnt.**
- 예측보다 0~6개 많다. 원인은 확인 안 함(백로그 실제 칸 수가 정확히 200이 아니거나, 측정 타이밍). 용량 계산에 주는 영향은 1~2%.
