# TCP_NODELAY 켬/끔 - PC A 한 대 (2026-11-23)

## 조건
- PC A(Core Ultra 5 125U, 하이브리드), 게임 서버·로그인 서버·Redis·MySQL·봇 모두 한 PC, 루프백
- 봇 30개(입장 → 0.5–3초마다 채팅, 방 하나에 방송), 120초, 켬/끔을 번갈아 3회(회차마다 순서를 바꿈)
- 서버 설정 `tcpNoDelay`(server.cfg, 0 = OS 기본 Nagle 켬 / 1 = 수락한 소켓마다 TCP_NODELAY). 봇(클라)은 TCP_NODELAY를 쓰지 않는다
- 채팅 왕복 = 봇이 채팅을 보낸 때 → 방송으로 자기 채팅을 받은 때. p50·p99는 5초 구간 값의 중앙값, 최대는 전 구간 최대. 첫 구간(입장 중) 제외
- 시험 `tools/game/nodelay.ps1 -Rounds 3 -Sec 120 -Bots 30`

## 해석
- Nagle은 "보낸 데이터의 ACK가 아직 안 왔는데 MSS보다 작은 데이터를 또 보낼 때"만 붙잡는다. 이 부하에서는 봇 하나가 방송을 약 60ms마다 받고, 루프백 ACK는 그보다 훨씬 빨리 돌아와 붙잡힐 일이 거의 없다(추정 - ACK 시각은 재지 않음)
- 라이브러리가 이미 세션마다 WSASend를 하나만 걸고 그 사이 메시지를 모아 보내므로, Nagle이 하는 "작은 송신 모으기"를 라이브러리가 먼저 한다
- 실제 네트워크(왕복 수 ms, 받는 쪽 지연 ACK)에서는 결과가 다를 수 있다 - 두 PC(PC B 게임 서버, PC A 로그인 서버·봇)에서 다시 잰다
