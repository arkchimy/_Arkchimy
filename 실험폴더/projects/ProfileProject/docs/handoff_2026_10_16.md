## 1. 목표

여러 스레드가 동시에 측정해도 안전한 프로파일러 라이브러리를 처음부터 만든다.
태그별로 `호출 횟수 / 평균 / 최소 / 최대` 시간을 스레드별로 모으고, 파일로 저장한다.

핵심 원칙: **기록 경로(측정할 때마다 실행되는 코드)에서 스레드끼리 아무것도 공유하지 않는다.**

## 3. 전체 구조

```
                         ┌──────────── 전역 (g_registryLock 보호) ────────────┐
                         │  g_profiles: [ ptrA, ptrB, ... ]  (해제하지 않음)    │
                         └─────────┬───────────────┬───────────────────────────┘
                                   │               │
   스레드 A                        ▼               ▼                스레드 B
   thread_local t_profile ──▶ 힙: ThreadProfile A   힙: ThreadProfile B ◀── thread_local t_profile
                              ├ lock  (A 전용)      ├ lock  (B 전용)
                              ├ name  "Worker_1"    ├ name  "Worker_2"
                              └ samples[64]         └ samples[64]
                                 [0] "Work" ...        [0] "Work" ...

   ProfileScope (스택)                               Profile::Save (아무 스레드)
   ├ mSample ─▶ samples[i]                           1. g_registryLock → 포인터 목록 복사
   └ mStart  (시작 QPC)                              2. 각 lock → memcpy 스냅샷 (락은 복사 동안만)
                                                     3. 이름순 정렬 → 락 밖에서 fprintf
```

### 락 3종류와 잡는 빈도

| 락 | 보호 대상 | 언제 잡나 | 기록 경로 영향 |
|---|---|---|---|
| `g_registryLock` (전역) | `g_profiles` vector | 스레드 첫 측정 시 1회, 저장 시 1회 | 없음 |
| `ThreadProfile::lock` (스레드별) | 그 스레드의 `samples`, `sampleCount`, `name` | 소멸자마다, 새 칸 추가, 이름 지정, 저장 시 복사 | 있음 (원자 연산 1회, 경합 상대는 저장 스레드뿐) |
| `g_saveLock` (전역) | 출력 파일 | `Profile::Save()` 전체 | 없음 |

### 측정 타이밍
```
생성자:  [태그 탐색 / 새 칸 추가]  →  QPC 읽기(mStart)        ← 탐색 비용이 측정에 안 섞이게 마지막
         ───────────── 측정 구간 ─────────────
소멸자:  QPC 읽기(end)  →  [nullptr 검사 / 락 / 통계 갱신]   ← 락 대기·갱신 비용이 안 섞이게 처음
```

## 4. 설계 결정 (오늘 순서대로)

### 4-1. 전역 map + 락 → 기각
- 모든 스레드가 같은 락을 기다림 (직렬화).
- 측정값 자체가 오염됨: 락 대기 시간이 측정에 섞이고, 원래 병렬인 코드가 직렬로 바뀜.
- → **스레드별 저장소 (`thread_local`)** 로 결정.

### 4-2. 태그 찾기: 포인터 비교 → 기각, 전역 태그 ID 등록 → 기각, strcmp 선형 탐색 → 채택
- 포인터 비교: 같은 문자열 리터럴이라도 cpp/DLL이 다르면 주소가 같다는 보장이 없음 (유저 지적).
- 호출 위치마다 static ID 발급(`RegisterTag`): 전역 테이블이 필요해서 기각.
- 채택: 각 스레드가 자기 `samples`에서 `strncmp`로 탐색. 공유 없음, 대신 태그 수만큼 선형 비용.

### 4-3. RAII (`ProfileScope`) 채택, 매크로 사용 안 함
- 스코프를 벗어나면 소멸자가 반드시 실행 → `End` 누락, 중간 `return`, 예외에도 안전.
- 시작 시각(`mStart`)을 스택 객체가 들고 있으므로 같은 태그가 중첩돼도 서로 덮어쓰지 않음.
- 매크로(`__LINE__` 붙이기)는 읽기 어려워서 쓰지 않음.

### 4-4. 타입/시간: `__int64` → `int64_t`, chrono 대신 QPC
- 통계는 QPC 틱 단위로 누적, **출력할 때만** `QueryPerformanceFrequency`로 us 변환
  → 기록 경로에 나눗셈 없음.

### 4-5. 태그 문자열: 포인터 저장 → 복사 저장 (`char tag[32]`)
- 포인터 저장 시 `std::string::c_str()` 같은 임시 문자열이면 댕글링 → 다음 strcmp에서 해제된 메모리 읽음.
- 복사로 변경. 비교도 `strcmp` → `strncmp(..., MAX_TAG_LEN - 1)`:
  31자 넘는 태그는 잘려 저장되므로 strcmp로는 영원히 불일치 → 매 호출마다 새 칸 추가 → 64칸 소진.
  대가: 앞 31자가 같은 다른 태그는 하나로 합쳐짐.

### 4-6. `MAX_SAMPLE`: `constexpr int` 유지 (enum 기각)
- enum이 메모리를 아낀다는 제안 → 실제 차이 없음.
  네임스페이스 범위 `constexpr int`는 내부 링크이고, 값으로만 쓰면 즉시값으로 들어가 저장 공간이 안 생김.

### 4-7. 집계 동기화: 전역 shared_lock 기각 → **스레드별 `std::mutex`** 채택
- 전역 락 하나를 shared로 잡으면 대기는 없어도 락 변수 캐시라인이 코어 사이를 오감 (핑퐁).
- 스레드별 락: 평소엔 자기 스레드만 잡아서 캐시라인이 자기 코어에 머묾. 경합 상대는 저장 스레드뿐.
- 대안이었던 relaxed atomic(필드 간 순간 불일치 허용)은 선택 안 함. SRWLOCK 대신 `std::mutex`(유저 선택).
- 생성자의 **탐색은 락 없음**: 그 스레드만 쓰는 데이터를 그 스레드가 읽는 것이라 충돌 없음.

### 4-8. 스레드 종료 시 댕글링 → **ThreadProfile을 힙에 만들고 해제하지 않음**
```
변경 전: thread_local ThreadProfile t_profile;   → 스레드 종료 시 파괴 → 전역 목록의 포인터 댕글링
변경 후: thread_local ThreadProfile* t_profile;  → 데이터는 힙, 스레드가 끝나도 남음
```
- 장점: 종료된 스레드의 통계도 결과에 포함, 댕글링 원천 차단.
- 비용: 스레드 수 × 약 4KB가 남음. 서버는 스레드 수가 고정이라 상한이 있음.
- 기각한 대안: 종료 시 등록 해제 → 통계 소실 + 집계 중 해제를 막기 위한 추가 동기화 필요.
- `new ThreadProfile()`의 `()` 필수: 빼면 samples/sampleCount가 쓰레기값.

### 4-9. 출력 형식
- 스레드별 구분 출력 (합산 아님, 유저 선택) → 특정 스레드만 느린 경우를 찾을 수 있음.
- 스레드 ID 대신 이름 (`Profile::SetThreadName`, 기본값 `Thread_<ID>`).
  `SetThreadDescription`은 와이드 문자열이고 종료된 스레드는 읽을 수 없어서 기각.
- 저장 시 스냅샷을 먼저 뜨고 이름순 정렬 (등록 순서는 실행마다 달라짐).

### 4-10. 파일 저장
- 파일명: `실행파일명_YYYYMMDD_HHMMSS_Profiler.txt`, 시각은 **프로세스 시작 시각**(`GetProcessTimes`)
  → 실행 한 번에 파일 하나, 저장할 때마다 `"w"`로 덮어씀.
- 같은 파일을 쓰므로 동시 저장을 막기 위해 `g_saveLock`으로 저장 전체 직렬화.

## 5. 실험으로 확인한 사실

### 5-1. Max가 평균의 10배 이상인 원인
- 첫 가설(유저): 캐시 미스 → 크기가 안 맞음. 미스 1회 약 100ns, `Work()`는 데이터가 거의 없어 많아야 1us 수준.
  실제 증가폭은 100us 이상.
- 검증 방법(유저 제안): **`maxSeq`(Max가 기록된 호출 순번)** 추가.
- 결과 (1000회 × 5번 실행): MaxSeq = 41, 712, 383, 118, 900, 960, 121, 698, 601, 956
  → 1번째는 한 번도 없음, 아무 때나 발생.
- 결론: 첫 호출(콜드 스타트)·캐시 미스 기각. **인터럽트/컨텍스트 스위치처럼 OS가 끼어드는 것**이 유력.
  장시간 실행에서는 Max 15~17ms도 관측 → Windows 스레드 퀀텀(약 15.6ms)과 같은 크기 → 선점 후 대기로 추정.

### 5-2. 이상치는 평균에서 빼지 않음 (유저 결정)
- 표본이 많아지면 희석됨. OS 개입도 서버가 실제로 치르는 비용.
- 이상치 자체는 Max / MaxSeq로 따로 확인.

### 5-3. 기록 중 동시 저장
- 워커 2개가 계속 기록하는 동안 메인이 1초마다 저장 → 5초간 크래시 없음, Count 정상 증가 (초당 약 15만).
- **단, 이건 "안전하다"는 증명이 아님.** 경쟁 상태는 타이밍이 맞아야 드러남 → 다음 할 일 참고.

## 7. 오후 작업 (2026-10-16)

오전에 만든 프로파일러를 정리하고, 라이브러리로 분리한 뒤 FloodClient에 붙였다.

### 7-1. 공개 함수를 `Profile` 네임스페이스로 묶음
```
변경 전                       변경 후
ProfileSetThreadName(name) →  Profile::SetThreadName(name)
ProfileSave()              →  Profile::Save()
(없음)                     →  Profile::Reset()
ProfileScope               →  ProfileScope (그대로, 전역)
```
- 함수 2개만 감쌈 (유저 선택). 구조체, `ProfileScope`, 상수는 전역에 그대로 둠.
- cpp에서는 `namespace { }` 블록 대신 `bool Profile::Save()`처럼 한정 이름으로 정의
  → 헤더 선언과 시그니처가 다르면 컴파일 에러가 나서 오타가 바로 잡힘.

### 7-2. 검토하고 채택하지 않은 것

**`shared_ptr<ThreadProfile>` → 기각 (원시 포인터 유지)**
```
thread_local shared_ptr  (참조 1) ─┐
g_profiles의 shared_ptr  (참조 2) ─┴─▶ ThreadProfile
스레드 종료 → 참조 1 / 프로세스 종료 → 0 → delete
```
- 전역 목록이 항상 참조 하나를 쥐고 있어서, 참조 수가 0이 되는 건 프로세스 종료 때뿐
  → "공유"의 의미가 없고, 지금의 "해제하지 않음"과 같다.
- 오히려 종료 시 `g_profiles` 파괴 순간에 아직 기록 중인 스레드가 있으면 해제된 메모리 접근.
  해제하지 않으면 이 문제가 원천적으로 없다.

**싱글톤 매니저 클래스 → 기각 (전역 함수 + cpp `static` 유지)**
- cpp의 `static` 전역 변수 + 공개 함수 = 이미 "숨겨진 싱글톤" (인스턴스 하나, 외부 접근 불가).
- 싱글톤 클래스는 private 멤버를 헤더에 선언해야 해서 `<mutex>`, `<vector>`가 헤더로 노출됨.
- 초기화 순서 문제는 클래스가 아니어도 함수 안 `static`으로 해결 가능.

**헤더 정리 (구조체를 cpp로 옮기기) → 논의만 함, 미적용**
- `ProfileScope`의 멤버 `mSample`이 **포인터**라서 `struct ProfileSample;` 전방 선언만으로 컴파일됨.
  (값 멤버였다면 `sizeof(ProfileScope)`를 몰라서 불가 — Pimpl과 같은 원리)
- 옮기면 `ProfileSample`, `ThreadProfile`, `MAX_SAMPLE`, `MAX_TAG_LEN`, `<mutex>`가 헤더에서 빠짐.
  `MAX_THREAD_NAME_LEN`은 사용자가 이름 버퍼 크기로 쓰므로 헤더에 남김.

**파일 출력을 버퍼에 모아 `fwrite` 1회 → 기각 (`fprintf` 유지)**
- `fprintf`는 CRT 버퍼(기본 4KB)를 거치므로 매번 시스템 콜이 나가지 않는다.
  매번 드는 건 서식화 + 스트림 락뿐.
- `Save()`는 키를 눌렀을 때만 도는 함수라 핫패스가 아님.
- 버퍼 방식은 줄 버퍼 길이 관리가 새로 생김: `sprintf_s`는 넘치면 프로세스 종료.
  (현재 서식의 최대 줄 길이는 약 160B라 256B를 넘지 않지만, 컬럼이 늘면 깨질 수 있음)

### 7-3. `Profile::Reset()` 추가
- 모든 스레드의 `total, min(INT64_MAX), max, maxSeq, count`를 새 칸 추가 때와 같은 값으로 되돌림.
  **tag와 sampleCount는 유지** (칸은 그대로, 통계만 초기화). avg는 저장값이 아니라 출력 시 계산.
- `g_saveLock`을 같이 잡음 → `Save()`와 동시에 돌면 "일부 스레드는 리셋 전, 일부는 리셋 후"로
  저장되는 것을 막음.
- 스레드별 락 안에서 초기화 → 기록 스레드의 소멸자와 겹치지 않음.
- 알려진 한계: 리셋 직전에 시작해서 직후에 끝난 측정 1회는 새 구간으로 들어감 (무시 가능).
- 생성자의 새 칸 초기화와 5줄 중복 — 함수로 묶는 건 보류.

### 7-5. 키 입력으로 저장/리셋
테스트 앱, NetworkLib, FloodClient의 `main.cpp` 모두 같은 방식 (`_getch`, 대소문자 무관):

| 키 | 동작 |
|---|---|
| A | `Profile::Save()` |
| D | `Profile::Reset()` |
| Q | 종료 |

- 테스트 앱은 기존 "5초 동안 1초마다 자동 저장"을 없애고 키 입력으로 바꿈.

### 7-7. FloodClient에 측정 코드 부착 (ConnectEx가 느린 이유 측정용)
배경: connect-close 반복 워크로드에서 블로킹 connect 약 20,000 TPS, ConnectEx+IOCP 약 2,500 TPS
(`networkLibProject/docs/handoff_2026_10_15.md` 10절). 어느 단계가 비싼지 재기 위해 단계별로 태그를 붙임.

```
postConnect (슬롯 1개 등록)                  workerLoop (워커 스레드)
┌──────────────────────────┐                ┌───────────────────────────────────────┐
│ Flood_Socket             │ 공통           │ Flood_GQCS          ConnectEx 전용    │
│ Flood_Bind               │ ConnectEx 전용 │ ┌ Flood_Complete (루프 한 바퀴 전체) ─┐│
│ Flood_IocpRegister       │ ConnectEx 전용 │ │ Flood_UpdateContext  (성공 경로)   ││
│ Flood_ConnectEx          │ connect에 대응 │ │ Flood_GetOverlappedResult (실패)   ││
└──────────────────────────┘                │ │ Flood_SetLinger      공통          ││
             ▲                              │ │ Flood_CloseSocket    공통          ││
             └──────── 같은 슬롯 재등록 ────┼─┤ postConnect(ov) ──────────────────┘│
                                            └───────────────────────────────────────┘
```
- 스레드 이름: 워커 `FloodWorker_0~N` (프로파일러 + `SetThreadDescription`), 통계 스레드 `FloodStat`
  (`SetThreadDescription`만). 처음 slotCnt개를 거는 `init`의 `postConnect`는 main 스레드
  (`Thread_<ID>`)에 따로 찍힘.
- `ConnectEx` 에러 코드는 스코프 안에서 한 번만 읽도록 바꿈 (소멸자의 기록 코드가 last error를
  덮어쓸 여지 제거, 동작 변화 없음).
- 읽는 법:
  - `Flood_GQCS`에는 완료가 없어 쉬는 시간도 포함 → 부하가 안정된 뒤 D(리셋) → 일정 시간 → A(저장).
  - `Flood_Socket` Count > `Flood_ConnectEx` Count → 차이 = bind/IOCP 등록 실패 후 재시도.
  - `Flood_ConnectEx` Count > 완료 건수 → 차이 = 동기 실패 후 재시도.
  - 바깥 스코프(`Flood_Complete`)에는 안쪽 스코프들의 기록 비용(스코프당 수십 ns)도 포함.

### 7-8. networkLibProject에도 부착됨 (요청 착오)
"AcceptEx가 느린 이유"를 서버 쪽으로 잘못 이해해서 서버에도 같은 방식으로 붙였다.
나중에 서버 쪽 AcceptEx를 잴 때 쓸 수 있다.
- 태그: `AcceptEx_Socket`, `AcceptEx_Post`, `AcceptEx_GQCS`, `AcceptEx_Complete`(AcceptEx 모드),
  `Accept_Accept`(accept 모드), `CloseReset_SetLinger`, `CloseReset_CloseSocket`(공통, `SocketUtil.cpp`).
- 스레드 이름: `AcceptExWorker_N`, `AcceptThread`.
- 프로파일러로 못 재는 서버 쪽 의심 항목:
  1. 동시에 걸어 두는 AcceptEx가 `workerCnt`(4)개뿐.
  2. AcceptEx로 받은 소켓에 `SO_UPDATE_ACCEPT_CONTEXT` 미설정 → FloodClient의 TIME_WAIT 문제와
     같은 현상(LINGER 무시)이 서버에도 있을 수 있음. `netstat -an | find "TIME_WAIT" /c`로 확인.

### _lib/ProfilerLib/Profiler.h
```cpp
#pragma once
#include <windows.h>
#include <cstdint>
#include <mutex>

// 스레드 하나가 기록할 수 있는 최대 태그 수
constexpr int MAX_SAMPLE = 64;

// 태그 문자열 최대 길이 (널 문자 포함, 넘으면 잘림)
constexpr int MAX_TAG_LEN = 32;

// 스레드 이름 최대 길이 (널 문자 포함, 넘으면 잘림)
constexpr int MAX_THREAD_NAME_LEN = 32;

// 태그 하나에 대한 통계
struct ProfileSample
{
    char        tag[MAX_TAG_LEN];   // 복사해서 보관 (원본 수명과 무관)
    int64_t     total;    // QPC 틱 단위
    int64_t     min;
    int64_t     max;
    int64_t     maxSeq;   // max가 기록된 호출 순번 (1부터)
    int64_t     count;
};

// 스레드 하나가 가진 기록 전체
struct ThreadProfile
{
    std::mutex    lock;                 // 이 스레드 전용 락 (상대는 집계 스레드뿐)
    char          name[MAX_THREAD_NAME_LEN];   // 출력용 스레드 이름 (기본값 "Thread_<ID>")
    ProfileSample samples[MAX_SAMPLE];
    int           sampleCount;
};

// 스톱워치 객체: 생성자에서 시작, 소멸자에서 정지 후 기록
class ProfileScope
{
public:
    explicit ProfileScope(const char* tag);
    ~ProfileScope();

    ProfileScope(const ProfileScope&) = delete;
    ProfileScope& operator=(const ProfileScope&) = delete;

private:
    ProfileSample* mSample;   // 생성자에서 찾아둔 항목 (t_profile 안의 칸)
    int64_t        mStart;    // 시작 시각 (QPC 틱)
};

namespace Profile
{
    // 지금 스레드의 출력용 이름 지정 (예: "AcceptThread_1"), 스레드 시작 시 1회 호출
    void SetThreadName(const char* name);

    // 모든 스레드의 통계를 "프로젝트명_날짜_시간_Profiler.txt" 파일로 저장 (실패 시 false)
    // 날짜/시간은 exe 실행 시각 기준이라 실행 중에는 같은 파일에 덮어씀
    bool Save();

    // 모든 스레드의 통계(total, min, max, maxSeq, count)를 초기화, 태그와 스레드 이름은 유지
    void Reset();
}
```

### _lib/ProfilerLib/Profiler.cpp
```cpp
#include "Profiler.h"
#include <algorithm>
#include <cstring>
#include <cstdio>
#include <vector>

// 집계용 전역 목록: 모든 스레드의 ThreadProfile 주소 (해제하지 않음)
static std::mutex                  g_registryLock;
static std::vector<ThreadProfile*> g_profiles;

// 스레드마다 별도로 존재하는 포인터 (실제 데이터는 힙에 있어 스레드 종료 후에도 남음)
thread_local ThreadProfile* t_profile = nullptr;

// 지금 스레드의 ThreadProfile 반환, 처음 호출이면 생성 후 전역 목록에 등록
static ThreadProfile* GetThreadProfile()
{
    if (t_profile != nullptr)
    {
        return t_profile;
    }

    // () 를 붙여 값 초기화 → samples, sampleCount 모두 0
    ThreadProfile* profile = new ThreadProfile();

    // 이름을 지정하지 않은 스레드도 구분되도록 기본 이름 부여
    sprintf_s(profile->name, MAX_THREAD_NAME_LEN, "Thread_%lu", GetCurrentThreadId());

    {
        // 스레드당 한 번만 실행되므로 전역 락이어도 기록 경로에 영향 없음
        std::lock_guard<std::mutex> guard(g_registryLock);
        g_profiles.push_back(profile);
    }

    t_profile = profile;
    return profile;
}

void Profile::SetThreadName(const char* name)
{
    ThreadProfile* profile = GetThreadProfile();

    // Profile::Save가 이름을 읽는 도중에 바뀌지 않도록 락 안에서 복사
    std::lock_guard<std::mutex> guard(profile->lock);
    strncpy_s(profile->name, MAX_THREAD_NAME_LEN, name, _TRUNCATE);
}

ProfileScope::ProfileScope(const char* tag)
{
    ThreadProfile& profile = *GetThreadProfile();

    // 1. 같은 태그가 이미 있는지 탐색
    ProfileSample* sample = nullptr;
    for (int i = 0; i < profile.sampleCount; ++i)
    {
        // 저장된 태그는 잘렸을 수 있으므로 저장 가능한 길이까지만 비교
        if (strncmp(profile.samples[i].tag, tag, MAX_TAG_LEN - 1) == 0)
        {
            sample = &profile.samples[i];
            break;
        }
    }

    // 2. 없으면 새 칸 추가 (가득 찼으면 nullptr → 소멸자에서 기록 생략)
    if (sample == nullptr && profile.sampleCount < MAX_SAMPLE)
    {
        // 집계 스레드가 sampleCount와 새 칸을 읽을 수 있으므로 쓰기는 락 안에서
        std::lock_guard<std::mutex> guard(profile.lock);

        sample = &profile.samples[profile.sampleCount];
        ++profile.sampleCount;

        strncpy_s(sample->tag, MAX_TAG_LEN, tag, _TRUNCATE);   // 넘치면 잘라서 널 종료
        sample->total = 0;
        sample->min   = INT64_MAX;   // 첫 기록이 무조건 min이 되도록
        sample->max    = 0;
        sample->maxSeq = 0;
        sample->count  = 0;
    }

    mSample = sample;

    // 3. 시작 시각은 맨 마지막에 읽음 (탐색 비용이 측정값에 섞이지 않게)
    LARGE_INTEGER now;
    QueryPerformanceCounter(&now);
    mStart = now.QuadPart;
}

ProfileScope::~ProfileScope()
{
    // 1. 종료 시각은 맨 먼저 읽음 (갱신 비용이 측정값에 섞이지 않게)
    LARGE_INTEGER now;
    QueryPerformanceCounter(&now);

    // 생성자에서 칸을 못 받았으면 (MAX_SAMPLE 초과) 기록 생략
    if (mSample == nullptr)
    {
        return;
    }

    // 2. 통계 갱신
    int64_t elapsed = now.QuadPart - mStart;

    // 생성자에서 GetThreadProfile()을 거쳤으므로 t_profile은 nullptr이 아님
    std::lock_guard<std::mutex> guard(t_profile->lock);

    mSample->total += elapsed;
    ++mSample->count;

    if (elapsed < mSample->min)
    {
        mSample->min = elapsed;
    }

    if (elapsed > mSample->max)
    {
        mSample->max    = elapsed;
        mSample->maxSeq = mSample->count;   // 위에서 증가시킨 뒤라 1부터 시작
    }
}

// 파일 저장 직렬화용 (여러 스레드가 동시에 Profile::Save를 호출하면 같은 파일에 섞여 써지므로)
static std::mutex g_saveLock;

// "프로젝트명_날짜_시간_Profiler.txt" 형식의 파일 이름 생성
// 프로젝트명 = 실행 파일 이름, 날짜/시간 = 프로세스 시작 시각 → 실행 한 번에 파일 이름 하나
static void MakeProfileFileName(char* outFileName, int outSize)
{
    char exePath[MAX_PATH];
    GetModuleFileNameA(nullptr, exePath, MAX_PATH);

    // 경로 제거: "C:\...\ProfileProject.exe" → "ProfileProject.exe"
    const char* exeName = strrchr(exePath, '\\');
    if (exeName != nullptr)
    {
        ++exeName;
    }
    else
    {
        exeName = exePath;
    }

    // 확장자 제거: "ProfileProject.exe" → "ProfileProject"
    char projectName[MAX_PATH];
    strncpy_s(projectName, MAX_PATH, exeName, _TRUNCATE);

    char* dot = strrchr(projectName, '.');
    if (dot != nullptr)
    {
        *dot = '\0';
    }

    // 프로세스 시작 시각 (UTC) → 로컬 시각으로 변환
    FILETIME creationTime;
    FILETIME exitTime;
    FILETIME kernelTime;
    FILETIME userTime;
    GetProcessTimes(GetCurrentProcess(), &creationTime, &exitTime, &kernelTime, &userTime);

    FILETIME localCreationTime;
    FileTimeToLocalFileTime(&creationTime, &localCreationTime);

    SYSTEMTIME start;
    FileTimeToSystemTime(&localCreationTime, &start);

    sprintf_s(outFileName, outSize, "%s_%04d%02d%02d_%02d%02d%02d_Profiler.txt",
        projectName,
        start.wYear, start.wMonth, start.wDay,
        start.wHour, start.wMinute, start.wSecond);
}

bool Profile::Save()
{
    std::lock_guard<std::mutex> saveGuard(g_saveLock);

    char fileName[MAX_PATH];
    MakeProfileFileName(fileName, MAX_PATH);

    // "w" 모드: 파일이 있으면 내용을 비우고 처음부터 씀 (덮어쓰기)
    FILE* file = nullptr;
    if (fopen_s(&file, fileName, "w") != 0 || file == nullptr)
    {
        return false;
    }

    LARGE_INTEGER freq;
    QueryPerformanceFrequency(&freq);
    double tickToUs = 1000000.0 / static_cast<double>(freq.QuadPart);

    // 1. 전역 목록은 복사만 하고 바로 락 해제 (출력 중에 새 스레드 등록을 막지 않도록)
    std::vector<ThreadProfile*> profiles;
    {
        std::lock_guard<std::mutex> guard(g_registryLock);
        profiles = g_profiles;
    }

    // 2. 스레드별 복사본 생성 (스레드 락은 복사하는 동안만 잡음 → 파일 쓰는 동안 기록 스레드가 기다리지 않도록)
    struct ThreadSnapshot
    {
        char          name[MAX_THREAD_NAME_LEN];
        ProfileSample samples[MAX_SAMPLE];
        int           sampleCount;
    };

    std::vector<ThreadSnapshot> snapshots(profiles.size());   // 스레드당 약 4KB라 스택 대신 힙

    for (size_t i = 0; i < profiles.size(); ++i)
    {
        ThreadProfile*  profile  = profiles[i];
        ThreadSnapshot& snapshot = snapshots[i];

        std::lock_guard<std::mutex> guard(profile->lock);
        memcpy(snapshot.name, profile->name, MAX_THREAD_NAME_LEN);
        snapshot.sampleCount = profile->sampleCount;
        memcpy(snapshot.samples, profile->samples, sizeof(ProfileSample) * snapshot.sampleCount);
    }

    // 3. 스레드 이름순 정렬 (등록 순서는 실행마다 달라서 출력 순서가 흔들림)
    std::sort(snapshots.begin(), snapshots.end(),
        [](const ThreadSnapshot& a, const ThreadSnapshot& b)
        {
            return strcmp(a.name, b.name) < 0;
        });

    // 4. 락 밖에서 파일에 기록
    for (const ThreadSnapshot& snapshot : snapshots)
    {
        fprintf(file, "[%s]\n", snapshot.name);
        // 마크다운 표 형식 (텍스트로 봐도 정렬되고, 마크다운 뷰어에서는 표로 보임)
        fprintf(file, "| %-31s | %10s | %14s | %14s | %14s | %10s |\n", "Tag", "Count", "Avg", "Min", "Max", "MaxSeq");
        fprintf(file, "|---------------------------------|------------|----------------|----------------|----------------|------------|\n");

        for (int i = 0; i < snapshot.sampleCount; ++i)
        {
            const ProfileSample& sample = snapshot.samples[i];

            // 칸만 추가되고 아직 소멸자가 안 돈 경우 (min이 INT64_MAX 상태)
            if (sample.count == 0)
            {
                continue;
            }

            double avg = static_cast<double>(sample.total) / static_cast<double>(sample.count);

            fprintf(file, "| %-31s | %10lld | %12.3fus | %12.3fus | %12.3fus | %10lld |\n",
                sample.tag,
                sample.count,
                avg * tickToUs,
                static_cast<double>(sample.min) * tickToUs,
                static_cast<double>(sample.max) * tickToUs,
                sample.maxSeq);
        }

        fprintf(file, "\n");
    }

    fclose(file);
    return true;
}

void Profile::Reset()
{
    // Save와 동시에 실행되면 일부 스레드는 초기화 전, 일부는 초기화 후 값으로 저장되므로 직렬화
    std::lock_guard<std::mutex> saveGuard(g_saveLock);

    // 전역 목록은 복사만 하고 바로 락 해제
    std::vector<ThreadProfile*> profiles;
    {
        std::lock_guard<std::mutex> guard(g_registryLock);
        profiles = g_profiles;
    }

    for (ThreadProfile* profile : profiles)
    {
        // 기록 스레드의 소멸자와 겹치지 않도록 스레드별 락 안에서 초기화
        std::lock_guard<std::mutex> guard(profile->lock);

        // 칸(tag, sampleCount)은 그대로 두고 통계만 생성자의 새 칸 추가와 같은 값으로 되돌림
        for (int i = 0; i < profile->sampleCount; ++i)
        {
            ProfileSample& sample = profile->samples[i];
            sample.total  = 0;
            sample.min    = INT64_MAX;
            sample.max    = 0;
            sample.maxSeq = 0;
            sample.count  = 0;
        }
    }
}
```

```cpp
#include "Profiler.h"
#include <atomic>
#include <cctype>
#include <conio.h>
#include <cstdio>
#include <thread>

// 워커 종료 신호 (메인이 쓰고 워커들이 읽음)
std::atomic<bool> g_running = true;

// 측정 대상 예시 함수
void Work()
{
    ProfileScope scope("Work");

    volatile int sum = 0;
    for (int i = 0; i < 10000; ++i)
    {
        sum += i;
    }
}

void ThreadMain(int index)
{
    char name[MAX_THREAD_NAME_LEN];
    sprintf_s(name, MAX_THREAD_NAME_LEN, "WorkerThread_%d", index);
    Profile::SetThreadName(name);

    // 메인이 종료 신호를 줄 때까지 계속 기록
    while (g_running)
    {
        Work();
    }
}

int main()
{
    std::thread t1(ThreadMain, 1);
    std::thread t2(ThreadMain, 2);

    printf("[A] Save  [D] Reset  [Q] Quit\n");

    // 워커가 기록하는 도중에 키 입력으로 저장/리셋 → 기록/집계 동시 접근 테스트
    // _getch는 키를 누를 때까지 메인 스레드만 대기 (워커는 계속 기록)
    bool quit = false;
    while (quit == false)
    {
        int key = toupper(_getch());

        switch (key)
        {
        case 'A':
            if (Profile::Save())
            {
                printf("Saved\n");
            }
            else
            {
                printf("Profile::Save failed\n");
            }
            break;

        case 'D':
            Profile::Reset();
            printf("Reset\n");
            break;

        case 'Q':
            quit = true;
            break;

        default:
            break;
        }
    }

    g_running = false;

    t1.join();
    t2.join();

    return 0;
}
```
