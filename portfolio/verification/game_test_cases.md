# 게임 서버 테스트 케이스

로그인 서버(가입·로그인, RSA 통로, Redis 세션 키)와 게임 서버(입장 2판, 암호 통로, 채팅방, 계정 행, 운영 툴)를 `tools/game/`의 시험 스크립트로 시험한다. 스크립트마다 서버·Redis를 띄우고 시험 클라에 명령을 넣은 뒤, 클라 출력·서버 통계·DB·Redis를 읽어 판정마다 PASS/FAIL을 낸다. 아래 판정은 마지막 전체 실행(2026-11-21, PC A)에서 모두 통과했다. `heartbeat`는 2026-11-23에 더했고, 그날 `run_all`(62판정)을 다시 돌려 통과했다.

- 오래 돌릴 때만 드러나는 문제(누수, 드문 경쟁, 멈춤)는 [봇 부하 시험](game_soak.md)이 맡는다
- 옛 구조(던전·경매) 때의 케이스는 지웠다 - 커밋 `5aa3cae`까지의 판에 있다

| 시험          | 잡으려는 문제                              | 판정 |
| ------------- | ------------------------------------------ | ---- |
| `auth_ok`     | 정상 경로가 깨짐                           | 10   |
| `entry_bad`   | 입장 우회(가짜·가로챈·순서 어긋난 패킷)    | 21   |
| `login`       | 남의 계정 입장, 키 재사용, 가짜 서버, 변조 | 29   |
| `chat`        | 받는 사람마다 순서가 다름, 길이 경계       | 9    |
| `login_race`  | 한 세션이 두 계정에 로그인                 | 3    |
| `restart`     | 재시작 뒤 계정·차단이 사라짐               | 6    |
| `reconnect`   | DB 연결이 끊긴 뒤 입장 실패                | 5    |
| `admin`       | 운영자 포트 노출, 차단 경로별 동작         | 7    |
| `login_edge`  | 두 서버 경계(장애·기한·대기열 상한)        | 43   |
| `login_flood` | 접속 폭주에 정상 로그인이 막힘             | 9    |
| `heartbeat`   | 입장 뒤 사라진 클라가 남음                 | 3    |

- `run_all.ps1`이 `login`·`chat`·`restart`·`reconnect`·`admin`·`login_race`·`heartbeat`를 차례로 돌린다(62판정, 약 4분). `login_edge`는 DB 표를 잠그고 `login_flood`는 약 4분이라 따로 돌린다
- 시험마다 필요한 계정을 DB에 직접 만들어(로그인 정보 포함) 서로 기대지 않고 몇 번이든 다시 돌릴 수 있다

## 1. `auth_ok` - 정상 경로 (판정 10개)

1. 가입 3명 성공
2. 첫 입장 3명 성공(처음 보는 아이디)
3. 첫 입장 뒤 계정 행 3줄
4. 두 번째 입장 3명 성공(같은 아이디, 새 세션 키)
5. 두 번째 입장 뒤에도 계정 행 3줄(새로 만들지 않음)
6. 어떤 클라도 서버가 먼저 끊지 않음
7. Redis에 남은 세션 키 0(입장 때 지움)
8. 로그인 서버: 로그인 성공 6 = 확인(AuthAck) 받음 6, 확인시간초과 0
9. 게임 서버: 입장확인실패·입장거절·잘못된패킷 0
10. 두 서버 세션 0

## 2. `entry_bad` - 입장 비정상 (판정 21개)

[입장 비정상 테스트 케이스](게임서버_입장_비정상_테스트케이스.docx) 3판의 26개(Hello 형식 H, 입장 요청 E, 리플레이 R, 입장 상태 S, 입장 뒤 메시지 M)를 판정 21개로 본다. 잘못된 바이트는 스크립트가 소켓으로 직접 보내고, 암호가 필요한 입장 요청은 클라 시험 명령 `enterdump`로 받은 시작값을 넣어 만든다. 서버는 이유를 알려 주지 않고 끊으므로 판정은 서버 통계의 증가분(입장확인실패·입장거절·잘못된패킷·입장기한끊김)과 Redis 키로 한다.

## 3. `login` - 로그인 서버와 세션 키 (판정 29개)

**가입·로그인**

1. 가입 성공
2. 같은 아이디 다시 가입 → 이미 있음
3. 짧은 비밀번호 → 거절
4. 틀린 비밀번호·없는 아이디 → 같은 실패 - 응답으로 어느 쪽인지 알려 주지 않는다
5. 맞는 비밀번호 → 게임 서버 입장
6. 한 연결 한 번 실패 뒤 다음 요청은 응답 없이 끊김(실패 응답은 받음) - 서버는 실패 응답 뒤 클라가 끊기를 기다린다(RST로 응답이 사라지지 않게)

**연결 상태**

7. 변조한 암호문 → 응답 없이 끊김
8. 로그인 성공 → 확인(AuthAck)을 보내면 서버가 바로 끊음(1초 안)
9. 로그인 성공 → 확인이 없으면 확인 기한(5초) 뒤 끊음
10. 로그인 성공 뒤 다시 로그인 요청 → 응답 없이 끊김
11. 한 연결에서 가입 두 번 → 응답 없이 끊김

**서버 확인(RSA 서명)**

12. 서버 공개 키가 다르면 → 서버 확인 실패, 비밀번호를 보내지 않음
13. 서명 한 바이트를 바꾼 HelloClient → 클라가 거절
14. 다른 연결이 받은 HelloClient → 클라가 거절
15. 같은 연결의 앞 응답을 다시 → 거절, 진짜 다음 응답은 통과

**세션 키와 입장**

16. 세션 키 받음
17. 확인 값이 틀린 입장 요청 → 입장 실패(응답 없이 끊김)
18. 틀린 입장 요청 뒤에도 진짜 키로 입장 - 키를 모르는 가짜 요청이 진짜 키를 지우지 못한다
19. 같은 키 다시 → 입장 실패(한 번만)
20. 30초 지난 키 → 입장 실패
21. Redis에 남은 키 0
22. 입장 뒤 암호문으로 채팅을 주고받음
23. 게임 구간 변조한 암호문 → 끊김
24. 입장 전 평문 명령 → 끊김

**Redis 장애와 정리**

25. Redis가 꺼지면 로그인 3번 모두 서버 오류
26. Redis가 꺼져도 오래 기다리지 않음(3번에 5초 안) - 연결 1초 제한, 실패 뒤 5초는 바로 실패
27. 게임 서버 세션 0
28. 로그인 서버 세션 0
29. 확인 기한으로 끊긴 연결은 확인을 안 보낸 시험 하나뿐(정상 로그인은 모두 확인을 보냄)

## 4. `chat` - 채팅방 (판정 9개)

1. 세 사람 입장 → 방 인원 3
2. 동시에 보낸 60줄을 세 사람 모두 받음
3. 보낸 사람별 순서가 그대로(A 0–29, B 0–29)
4. 받는 세 사람의 순서가 같음 - 방 락 안에서 방송한다
5. 한글 채팅(보낸 사람 포함)
6. 길이 1·200바이트 통과
7. 나간 사람은 방에서 빠짐(방 인원 2, 남은 사람끼리 채팅)
8. 0바이트·201바이트 채팅 → 끊김
9. 서버: 잘못된패킷 2, 끝난 뒤 세션 0·방 인원 0

## 5. `login_race` - 입장 중 이중 입장 (판정 3개)

처음 보는 아이디로 입장한 직후(DB 스레드가 읽는 중) 같은 연결에서 다른 입장을 또 보낸다. 경쟁 창은 나노초 수준이라 그 순간을 재현하는 것은 아니고, 고친 순서가 정상 경로를 깨지 않는지와 잠김이 없는지를 본다.

1. 이중 입장 세션은 모두 잘못된 패킷으로 끊김
2. 첫 아이디로 다시 입장 성공(잠김 없음)
3. 세션 0으로 돌아옴

## 6. `restart` - 재시작 (판정 6개)

1. 1회차: 처음 보는 아이디로 입장 성공
2. 1회차: 계정 행이 하나 생김
3. 1회차: 접속 중 차단 → 끊김
4. 2회차: 다시 켠 서버가 DB의 차단을 읽어 입장 실패
5. 2회차: 해제(DB에만 있던 계정을 메모리에 올린 뒤) → 입장 성공
6. 계정 행은 그대로 하나

## 7. `reconnect` - DB 연결 끊김 (판정 5개)

서버가 도는 중에 MySQL 쪽에서 서버의 연결을 `KILL`한다.

1. 서버 쪽 DB 연결을 끊음
2. 입장 성공(채팅이 돌아옴)
3. 끊김 감지 후 다시 연결
4. DB에 계정 행이 생김
5. DB 실패 0

## 8. `admin` - 운영 툴 (판정 7개)

1. 운영자 포트는 127.0.0.1에만
2. 키 없는 연결 4개가 5초 뒤 끊김 - 붙어만 있는 연결이 몇 안 되는 세션 칸을 막지 못하게
3. 분 입력 검증(빈 값·`1h` 거절)
4. 차단: DB에만 있는 계정·없는 계정·접속 중인 계정(끊김)
5. 차단 중 입장 실패(메모리 계정·DB에서 읽은 계정), 해제 뒤 입장 성공
6. DB: 차단 시각이 저장됨, 해제한 계정은 비워짐
7. 서버: 입장거절 2(차단 둘), 입장확인실패 0

## 9. `login_edge` - 두 서버의 경계 (판정 43개)

cpp-reviewer가 설계한 TC-L01–L12로, `login`이 지나가지 않는 경로를 본다. 1부: 잘못된 입력·길이 경계·세션 키 수명·같은 계정 새 입장(이전 접속 끊김)·처리 중 끊김·가로챈 입장 패킷(SeqNumber가 달라 끊김)·대기열 상한·Redis 재시작·멈춤·MySQL 끊김(DB 표를 `LOCK TABLES`로 잠가 DB 스레드를 붙잡는다). 2부: 요청이 남은 채 종료. 3부: 아무것도 보내지 않는 연결로 세션 칸 고갈(기한으로 정리). 이 시험이 찾아 고친 것은 첫 패킷 기한이 없던 것과 MySQL 연결이 끊긴 뒤 첫 읽기가 실패하던 것이다.

## 10. `login_flood` - 접속 폭주 (판정 9개)

HelloServer만 보내는 접속 0·50·200·400개를 연 직후 정상 로그인 5개를 시도한다. 서버 임시 키는 256개이고 연결이 끝나야 돌아온다.

1. 키 수 이하의 폭주(0·50·200개) 직후 정상 로그인 5개가 2초 안에 성공(판정 3개)
2. 키 수를 넘는 폭주(400개) 동안 새 접속은 바로 끊김
3. 키 수를 넘는 폭주가 요청 기한으로 정리된 뒤 정상 로그인 5개 성공
4. 키 쌍이 떨어진 뒤의 접속은 바로 끊김(키쌍부족끊김)
5. 연결이 모두 끝나면 키가 모두 풀로 돌아옴
6. 가입·로그인을 처리하는 워커는 워커 수(2) 이하
7. 로그인 서버 세션 0

## 11. `heartbeat` - 하트비트와 입장 뒤 유휴 기한 (판정 3개)

클라는 입장 뒤 10초마다 본문 없는 하트비트를 보내고, 게임 서버는 입장한 연결에서 `idleLimitSec`(기본 30초, 시험 동안 12초) 동안 아무것도 받지 못하면 끊는다. 송신 정체는 보낼 것이 있을 때만 걸려, 랜선이 뽑힌 클라는 이것으로 정리한다.

1. 하트비트를 보내는 클라는 20초 동안 채팅 없이도 남는다(그 뒤 보낸 채팅이 돌아옴)
2. 하트비트를 멈춘(`hbstop`) 클라는 서버가 끊는다
3. 서버: 무응답끊김 1, 잘못된패킷 0(하트비트를 받아들임)

## 다시 돌리기

빌드(`Game\Game.sln` Release x64)와 `Game/Server/db.cfg`·`Game/Login/login.cfg`가 필요하다. 저장소 맨 위에서:

```powershell
.\tools\game\run_all.ps1       # login·chat·restart·reconnect·admin·login_race·heartbeat
.\tools\game\auth_ok.ps1
.\tools\game\entry_bad.ps1
.\tools\game\login_edge.ps1    # 시험용 DB에서만(LOCK TABLES)
.\tools\game\login_flood.ps1
.\tools\game\soak.ps1 -Minutes 60 -Bots 30
```
