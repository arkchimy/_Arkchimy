## 2. 케이스별 깨 보는 방법과 근거

- **R1:** 무작위로 잘라 보낸 패킷 스트림을 EchoClient가 바이트 단위로 비교한다
- **R2:** 길이가 최대(4096)를 넘는 헤더를 보내는 클라(`client_badPacket.cfg`)
- **R3:** 길이 0, 4096, 4097인 패킷. 시험 클라 기능이 필요하다
- **S1:** 채팅 방 순번 검사. 일부러 넣은 버그가 잡히는지도 확인했다 - `room_move.md`
- **S2:** 방 이동 약 12만 번 + 순번 검사 - `room_move.md`
- **S3:** 송신 완료 처리 지연 주입(`testSendCompleteDelayMs`) - `send_path.md`
- **W1:** 워커가 아닌 스레드 2개 + 워커 에코를 섞은 시험(세션 1개) - `design/external_send.md`
- **W2:** 여러 세션에 방송하는 중 끊기. 아직 시험 프로그램이 없다
- **L1:** 연결·끊기 폭주에서 수락 수와 해제 수가 같은지, 세션이 0으로 돌아오는지
- **L2:** 해제 직후 같은 슬롯이 재사용될 때 옛 ID로 `SendPacket`/`Disconnect`를 부른다
- **L3:** 해제 작업 전달 실패 강제, 잘못된 핸들로 IOCP 호출 실패 - `design/lock_logic.md` 9-6, 9-7
- **D1:** 송수신이 계속되는 중에 `Disconnect`를 반복한다
- **D2:** 송신만 닫고(`shutdown`) 수신은 하지 않는 클라
- **N1:** 수신을 하지 않는 클라(`client_noRecv.cfg`)
- **N2:** 수신 윈도우 0 상황(`SO_SNDBUF = 0`, 정체 클라) - `design/timeout.md` 5장. 워커 밖 스레드가 맡긴 송신이 큐에서 기다리는 동안은 정체로 세지 않는다 - 2026-11-10 수정과 시험(`실험폴더/stall_fix_2026_11_10/`)
- **N3:** 침묵 클라, 하트비트만 보내는 클라 - `design/timeout.md` 6장
- **N4:** 서버 CPU 포화 + 문제 클라 4종 - `mixed_clients.md`
- **A1:** 최대 세션보다 많이 접속한다. `SessionFullCnt` 통계는 있으나 시험 기록을 찾지 못했다
- **A2:** 짧은 시간에 수천 번 접속·해제한다
- **T1:** 부하를 건 채 Ctrl+C로 종료한다. 지금 회귀 시험은 클라를 먼저 끈 뒤 종료한다
- **T2:** `Stop` → `Start`를 반복한다
- **H1:** 섞인 클라 구성을 1–3시간 돌린다
