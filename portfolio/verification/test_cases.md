# 테스트 케이스

에코 서버와 시험 클라(`Echo/Client`)로 네트워크 라이브러리를 시험했다. 아래 케이스는 모두 확인했다.

| 테스트 케이스                       | 실험한 이유                                                                                                                                                                                |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 회신 메시지의 순서·내용 검증        | 서버는 여러 응답을 모아 `WSASend` 한 번으로 보낸다. 모으는 과정에서 순서가 바뀌거나 내용이 섞이지 않는지 확인한다                                                                          |
| 송신을 멈춘 뒤 오지 않는 회신 검사  | 세션마다 송신 플래그로 `WSASend`를 하나씩만 건다. 플래그를 잘못 다루면 링에 보낼 데이터가 남아 있는데도 아무도 `WSASend`를 걸지 않는다. 요청을 멈추고 기다려 이 현상이 일어나는지 확인한다 |
| 비정상 길이 헤더 차단               | 헤더의 길이를 최대보다 크게 조작한 패킷이 오면, 라이브러리가 그 데이터를 기다리지 않고 즉시 끊는지 확인한다                                                                                |
| 송신 정체 연결 끊기                 | 상대가 읽지 않아 수신 윈도우가 0이 되어도 TCP는 연결을 끊지 않는다. 그런 연결이 서버 자원을 계속 잡지 않도록 라이브러리가 송신 정체 시간 기준으로 끊는지 확인한다                          |
| 클라 종료 방식(FIN·RST)별 세션 해제 | 끊김은 FIN이면 0바이트 수신 완료로, RST면 실패한 I/O 완료로 온다. 경로마다 I/O 카운트를 정확히 내려야 한다 - 놓치면 세션 슬롯이 돌아오지 않고, 두 번 내리면 사용 중인 세션이 해제된다      |
| 서버 종료 시 정리                   | 종료할 때 세션이 0으로 돌아오고, 워커·감시 스레드가 남은 일 없이 멈추는지 확인한다                                                                                                         |

## 시험 클라이언트

select 스레드 하나가 역할별 세션을 돌린다.

| 역할        | 하는 일                                                                                                                                | 판정                                                                          |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 정상        | 12바이트 요청 100개를 11바이트씩 잘라 보내고, 응답 100개를 받으면 다음 100개. 수명(30–60초)이 지나면 FIN과 RST를 번갈아 끊고 다시 접속 | 응답을 기대값과 비교해 다르면 그 자리에서 멈춤. 서버가 먼저 끊으면 예상밖끊김 |
| 비정상 헤더 | 길이가 `MAX_PAYLOAD_SIZE + 1` 또는 65535인 헤더만 보내고 끊기기를 기다림                                                               | 보낸 수 = 끊김을 확인한 수 = 서버 비정상헤더 수                               |
| 송신 정체   | 수신 버퍼 1KB, 응답을 읽지 않고 0.5초마다 요청 100개를 보냄                                                                            | 끊김을 확인한 수 = 서버 송신정체끊김 수                                       |

- **일시정지(S 키):** 정상 세션이 새 요청을 멈춘다. 연결된 정상 세션이 보낸 바이트에서 받은 바이트를 뺀 값(미수신)이 0이 되어야 하고, 멈춘 뒤 데이터가 더 오면 클라가 멈춘다.
- **종료(Q 키):** 진행 중인 요청의 응답까지 받고 닫는다. 정상 세션의 예상밖끊김과 종료 대기 초과가 0이면 `[result] PASS`를 출력한다.

## 조건과 결과

- 환경: Core Ultra 5 125U(14 논리 프로세서), 서버·클라 같은 PC 루프백, Release x64, 2026-11-12
- 서버 설정은 `Echo/Server/server.cfg` 기본값(워커 2, GQCSEx 64, 완료 통지 skip, 송신 정체 기준 10초) - 송신 정체 시험만 아래처럼 바꿨다

| 테스트 케이스                       | 조건                                                                     | 결과                                                                                                  |
| ----------------------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| 회신 메시지의 순서·내용 검증        | 4시간 시험: 정상 576 + 비정상 헤더 64, 4시간                            | 묶음 820만 개(요청 8.2억 개) 응답 불일치 0, 예상밖끊김 0                                              |
| 송신을 멈춘 뒤 오지 않는 회신 검사  | 4시간 시험 중 5분마다 일시정지, 최대 60초 대기                          | 47회 모두 2초 안에 미수신 0                                                                           |
| 비정상 길이 헤더 차단               | 4시간 시험                                                              | 보냄 614,592 = 끊김 확인 614,592 = 서버 비정상헤더 614,592                                            |
| 송신 정체 연결 끊기                 | 정상 576 + 송신 정체 64, 서버 `sendBufZero = 1`, `sendStallSec = 3`, 3회 | 3회 모두 클라 확인 수 = 서버 송신정체끊김 수, 끊기까지 4.0–6.7초, 넘침 끊김 0, 정상 세션 예상밖끊김 0 |
| 클라 종료 방식(FIN·RST)별 세션 해제 | 4시간 시험                                                              | FIN 89,785회, RST 89,483회, 수락 = 해제 794,436, 끝난 뒤 세션 0                                       |
| 서버 종료 시 정리                   | 4시간 시험 끝에 클라 종료 → 서버 종료                                   | 세션 0, `[main] 종료 완료`, 덤프 없음                                                                 |

- 송신 정체는 기준(3초)보다 늦게 끊긴다. 클라가 보낸 요청의 응답이 클라 수신 윈도우를 다 채워야 `WSASend`가 끝나지 않기 시작하고, 감시 스레드가 1초마다 보기 때문이다. 서버 송신 버퍼를 기본값으로 두면 커널 송신 버퍼까지 차야 해서 판정이 더 늦어지므로 `sendBufZero = 1`(커널 송신 버퍼 0)로 시험했다.
- 4시간 시험 동안 서버 메모리는 49MB로 그대로였고, 핸들은 시작 603개, 연결 640개가 붙은 동안 1242–1248개, 끝난 뒤 607개였다.

## 다시 돌리기

`Echo\Echo.sln`을 Release x64로 빌드한 뒤 저장소 맨 위에서 실행한다. 스크립트는 서버와 클라를 각자 콘솔로 띄우고 키(S, Q)를 넣으며, 끝나면 cfg를 원래대로 돌리고 결과 줄을 출력한다. 로그는 `%TEMP%\echo_test\<이름>\`에 남는다.

```powershell
# 4시간 시험 - 5분마다 일시정지하고 미수신이 0이 되는지 기록(pause_log.csv)
.\tools\echo_pause_test.ps1 -Name long -TotalMin 240 -IntervalSec 300 -ClientCfg "ip = 127.0.0.1;`nport = 32000;`nnormalCnt = 576;`nbadHeaderCnt = 64;`nlifeMinSec = 30;`nlifeMaxSec = 60;`n"

# 송신 정체 시험 - 서버 설정을 잠시 바꿔 30초
.\tools\echo_test.ps1 -Name stall -RunSec 30 -ServerCfg "sendBufZero = 1;`nsendStallSec = 3;" -ClientCfg "ip = 127.0.0.1;`nport = 32000;`nnormalCnt = 576;`nsendStallCnt = 64;`n"
```
