# 게임 서버 봇 부하 시험

봇 30개가 1시간 동안 로그인 → 게임 서버 입장 → 채팅 → 스스로 끊기를 반복하게 하고, 그동안 서버가 **조금씩 망가지는지**를 본다. 기능이 맞는지는 짧은 시험(`tools/game/run_all.ps1` 등)이 이미 확인한다. 이 시험은 짧은 시험으로는 드러나지 않는 문제 - 반복될수록 쌓이는 것, 드물게만 겹치는 순서 - 를 잡으려는 것이다.

- 대상: 게임 서버(입장 2판, 채팅방 하나)와 로그인 서버, MySQL, Redis
- 옛 구조(던전·경매) 때의 1·5시간 결과는 이 문서에서 지웠다 - 원본은 [실험폴더](../../실험폴더/)의 `game_soak_2026_11_15`–`11_17`

## 1. 잡으려는 문제

| 문제                  | 짧은 시험에서 안 보이는 이유    | 판정                 |
| --------------------- | ------------------------------- | -------------------- |
| 메모리 누수           | 한 번에 몇 바이트씩 쌓인다      | 증가 20% 이하        |
| 핸들 누수             | 재접속 수백 번에 하나씩         | 핸들 추이(보고)      |
| 세션 해제 누락        | 드문 순서에서만 짝이 어긋남     | 끝난 뒤 세션·방 0    |
| 데드락·멈춤           | 드문 락 순서 겹침               | 매 분 행동 수가 는다 |
| 정상 클라를 끊는 오판 | 부하·타이밍이 겹칠 때만         | 예상밖끊김 0         |
| 입장·채팅 순서 경쟁   | 응답 직후 움직일 때만           | 프로토콜오류 0       |
| 세션 키가 남음        | 입장 실패 경로에서만            | Redis 키 봇 수 이하  |
| DB 대기열 적체        | 1분 시험은 입장이 적다          | DB대기 최대 100 미만 |
| 드문 경쟁의 Assert    | 재접속·같은 계정 입장이 겹칠 때 | 덤프 없음, 정상 종료 |

- **세션 해제 누락:** 입장은 `HoldSession` → DB 스레드 → `UnholdSession`을 거치고, 끊기면 방에서 빼고 접속 표시를 지운다. 짝이 하나라도 어긋나면 그 칸은 돌아오지 않는다.
- **정상 클라를 끊는 오판:** 봇은 정상 클라가 할 수 있는 행동만 한다. 서버가 봇을 끊으면(송신 링 넘침, 송신 정체, 잘못된 패킷) 판정이 틀린 것이다 - 봇이 끊지 않았는데 끊긴 수를 `예상밖끊김`으로 센다.
- **입장·채팅 순서 경쟁:** 봇은 자기 채팅에 번호를 붙여 방송으로 돌아온 번호가 0부터 하나씩 오르는지 본다. 빠지거나 바뀌면 `프로토콜오류`다. 이 판정이 첫 1시간 시험에서 입장 응답과 방 넣기 사이의 틈을 찾았다(5장).

## 2. 조건

- 서버: `Game\x64\Release\GameServer.exe`·`LoginServer.exe`, `server.cfg` 기본값(워커 2, 입장 기한 60초, 로그인 서버 키 256개), MySQL 9.4·Redis 3.0(이 PC, 루프백)
- 봇: `GameBot.exe` 30개(계정마다 스레드 하나). 로그인 서버에서 세션 키를 받아 게임 서버에 입장하고, 30–90초 동안 0.5–3초마다 채팅한 뒤 스스로 끊고 다시 로그인한다
- 수집: 1분마다 서버 통계 한 줄(메모리, 핸들, 세션, 로그인, 방 인원, 채팅, DB대기, DB실패, 로그인 서버 메모리, Redis 키 수)과 봇 통계
- 실행: `.\tools\game\soak.ps1 -Minutes 60 -Bots 30` (결과 `%TEMP%\arkchimy_game_test\soak\`의 `samples.csv`, `server.txt`, `login.txt`, `bot.txt`)

## 3. 판정 기준(13개)

- 봇: 예상밖끊김·프로토콜오류·인증실패 0
- 서버: DB실패 0, 입장확인실패 0, 잘못된패킷·넘침끊김·송신정체끊김 0, 봇이 끝난 뒤 세션 0·방 인원 0, 정상 종료, 새 덤프 없음, 봇 계정 행 = 봇 수
- 진행: 매 분 봇 행동 수가 늘었다(멈춘 분 0), DB대기 최대 100 미만
- 메모리: 게임 서버·로그인 서버 모두 예열(전체의 20% 지점) 뒤 → 마지막 증가 20% 이하, 로그인 서버 잘못된패킷 0·정상 종료
- Redis: 세션 키 수 최대 봇 수 이하

## 4. 이 시험이 보지 못하는 것

- 서버·봇·MySQL·Redis가 한 PC의 루프백이라 네트워크 지연·손실은 없다
- 봇은 정상 행동만 한다 - 조작된 패킷은 `entry_bad.ps1`·`login_edge.ps1`이, 접속 폭주는 `login_flood.ps1`이 맡는다
- 처리량 한계는 재지 않는다(봇 30개는 서버를 포화시키지 않는다)
- 1시간은 운영 기간(며칠)보다 짧다
