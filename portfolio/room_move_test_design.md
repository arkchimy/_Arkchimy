# 방 옮기기 순서 검사 (설계 논의)

- 시작: 2026-11-03
- 상태: **2판 - 정함, 구현 중**
- 1판(ChatMsg에 방 번호 추가)은 사용자 개선안(입장·퇴장을 따로, 퇴장 완료 회신)으로 바뀌었다

---

## 1. 무엇을 확인하나

방을 옮기는 동안 받는 쪽에 다른 방 메시지가 섞이지 않는지. 지금까지는 코드로만 따진 결론이었고, LoadClient는 한 번만 입장해 방 이동을 시험하지 않았다.

## 2. 정한 것

### 2-1. 프로토콜 - 입장과 퇴장을 따로 둔다 (사용자)

| 패킷    | 방향        | 의미                                                        |
|---------|-------------|-------------------------------------------------------------|
| Join    | 클라 → 서버 | 방 입장. 이미 방에 있으면 잘못된 패킷(끊음)                 |
| JoinOk  | 서버 → 클라 | 새 방 락 안에서 넣는다 - 이 뒤에 오는 Chat부터 새 방 것     |
| Leave   | 클라 → 서버 | 방 퇴장. 방에 없으면 잘못된 패킷(끊음)                      |
| LeaveOk | 서버 → 클라 | 이전 방 락 안에서 빠지며 넣는다 - 이 뒤로 이전 방 Chat 없음 |

- `JoinOk`와 `LeaveOk`에는 그 순간 방의 마지막 순번(`Seq`)을 싣는다(cpp-reviewer 지적 반영). 받는 쪽은 첫 Chat이 `JoinOk.Seq + 1`인지, `LeaveOk.Seq`가 마지막으로 받은 순번과 같은지 본다 - 입장 직후 빠진 메시지와 퇴장 직전 빠진 메시지까지 잡는다

- 방을 옮기는 길은 `Leave` → `LeaveOk` → `Join` → `JoinOk` 하나뿐이다. 서버 `join`의 "자동으로 이전 방 빠지기"는 지운다
- 클라는 `Leave`를 보낸 뒤부터 `JoinOk`를 받기 전까지 Chat을 보내지 않는다. 서버는 방 밖에서 온 Chat을 지금처럼 끊는다
- 퇴장한 세션은 입장 제한 시간(`chatJoinSec`)을 퇴장 시각부터 다시 센다 - 방 밖에서 자리만 차지하는 것을 막는 규칙을 그대로 쓴다

### 2-2. 받는 쪽 검사

| 구간                  | 와도 되는 것                  | 오면 버그         |
|-----------------------|-------------------------------|-------------------|
| Leave 뒤–LeaveOk 전   | 이전 방 Chat (순번 +1 이어서) | -                 |
| LeaveOk 뒤–JoinOk 전  | 없음                          | **Chat 무엇이든** |
| JoinOk 뒤             | 새 방 Chat (첫 메시지부터 +1) | -                 |

- 방 밖에서 Chat이 오면 버그라 판정이 분명하다 - ChatMsg에 방 번호를 넣지 않아도 된다

### 2-3. 언제, 어디로 옮기나

- 자기 묶음이 다 돌아온 뒤, `roomMoveBatches`(LoadClient cfg, 0이면 끔)묶음마다 다음 묶음 대신 `Leave`
- `LeaveOk`를 받으면 다음 방(지금 방 + 1, 클라가 쓰는 방 수 안에서 순환)에 `Join`
- 시험 cfg `client_chatMove.cfg`, 출력에 `방이동` 수

- **순서 보장 확인**: 방을 옮기는 동안 다른 방 메시지는 한 번도 섞이지 않았다(4조건 약 12만 번 이동)
- **검사가 버그를 잡는지 확인 (퇴장 쪽)**: 서버에 "LeaveOk는 보내되 방에서는 빼지 않는" 버그를 일부러 넣자 클라가 1초 안에 `예상 밖 채팅 패킷 type=3 joined=0`(방 밖에서 Chat 받음)으로 멈췄다
- **cpp-reviewer 리뷰**: 순서 보장·감시 순서·끊김과 퇴장의 겹침·클라 상태 전이·코딩 규칙 모두 문제 없음. 다만 JoinOk에서 순번 기준을 0으로 되돌려 **입장 쪽 버그는 못 잡는다**는 지적 → JoinOk/LeaveOk에 `Seq`를 실어 검사를 강화
  - 강화 후 4조건 다시 통과(약 9.8만 번 이동)
  - **입장 쪽 버그 주입**: "JoinOk를 넣고 락을 놓은 뒤 1ms 뒤 구성원에 추가"하자 클라가 바로 `방 순번 어긋남 expected=1 actual=17`로 멈췄다(그 사이 방송 16개를 못 받음). 예전 검사로는 통과했을 버그다. 주입한 버그는 모두 지우고 다시 빌드했다
- **넘침은 방 옮기기 시험의 부하 때문**: 워커 4 · 묶음 단위에서 이동을 켜고 끄며 번갈아 3회 - 이동 켬 23/31/69건, 이동 끔 0/0/0건. 방을 옮기면 방 인원이 16명으로 고정되지 않아 받는 쪽에 몰리는 양이 늘어난다. 리뷰도 넘친 받는 사람은 끊기는 중이라 그 뒤 메시지가 링에 들어가지 않으므로 순서 보장과 무관하다고 확인. 넘침은 마지막 스트레스 테스트와 컨텐츠 제약(방 인원 상한 등)으로 다루기로 함(사용자) - README_ERRORS 2-7
